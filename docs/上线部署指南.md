# 上线部署指南（本地建好 → 租服务器 → 迁移）

## 零、本地开发与线上部署的关系

本地开发和线上运行使用的是同一套代码，差别只有一份配置文件：

| 项目 | 本地开发 | 线上 |
|---|---|---|
| 数据库 | SQLite（单文件，零安装） | PostgreSQL（Docker 里跑） |
| 后端地址 | `http://127.0.0.1:8000` | `https://你的域名/api` |
| 前端 | `npm run dev`（5173） | `npm run build` 出来的静态文件，由 nginx 提供 |
| 密钥 | 可以留空（每次启动随机） | **必须设置** `SECRET_KEY`，否则拒绝启动 |

项目遵循「配置不写死在代码里」的原则：数据库地址、密钥、跨域白名单、上传目录全部走环境变量（`.env`）。
迁移时不需要改任何一行业务代码，只需要：

1. 在服务器上填一份 `.env`；
2. 跑一次数据库迁移 + 导入基础数据；
3. 把前端构建产物交给 nginx。

本地完成的每一次功能开发，上线后都能原样跑起来。

## 一、买服务器和域名时要注意什么

### 服务器

| 选项 | 建议 | 说明 |
|---|---|---|
| 机型 | 2 核 4G（或 2 核 2G）轻量应用服务器 | 十几个班、几十号人使用，这个配置绰绰有余 |
| 系统 | Ubuntu 24.04 LTS | 下面的命令都按它写 |
| 机房 | 选离学校近的地域 | 延迟低一点，体验更好 |
| 带宽 | 3～5 Mbps 起 | 主要是文本和少量图片，压力很小 |
| 系统盘 | 40 GB 起 | 数据库和附件都在上面 |

> 记得在安全组里放行 **80 / 443**（HTTP/HTTPS）。**不要**放行 5432（数据库）和 8000（后端）——
> 这两个只在服务器内部的 Docker 网络里互通，外面访问不到才安全。

### 域名

1. 国内服务器 + 域名对外提供服务，**域名必须完成 ICP 备案**，否则 80/443 端口会被阻断。
   备案通常要 7～15 个工作日，各省略有差异，**建议早点提交**，别等系统要用了才开始。
2. 备案需要有：域名证书、身份证（或单位证件）、服务器（多数服务商要求服务器在其平台且时长 ≥ 3 个月）。
3. 备案通过后把域名解析到服务器公网 IP（`A` 记录），然后申请 HTTPS 证书。

### HTTPS 证书

两种都行：

- **云厂商免费 DV 证书**（腾讯云 / 阿里云都有一年期的免费证书），在控制台申请后下载 nginx 版；
- **Let's Encrypt**（90 天有效期，certbot 自动续期），前提是域名已备案且能正常解析。

拿到 `fullchain.pem` 和 `privkey.pem` 后放进 `deploy/certs/`，nginx 配置已经写好了引用路径。

## 二、迁移的完整步骤

默认服务器目录为 `/opt/attendance`，可以换成自己的路径。

### 1. 服务器装 Docker

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER   # 重新登录后生效
docker --version
```

### 2. 把代码放上去

```bash
sudo mkdir -p /opt/attendance && sudo chown $USER:$USER /opt/attendance
cd /opt/attendance
# 方式一：git
git clone <你的仓库地址> .
# 方式二：本地压缩后上传（scp / rsync）
#   rsync -av --exclude node_modules --exclude .venv ./ user@服务器IP:/opt/attendance/
```

### 3. 安装 Node 依赖并构建前端

```bash
cd /opt/attendance
npm ci
npm run build          # 产出 dist/，nginx 直接托管它
```

> 如果服务器上不想装 Node，也可以在本地 `npm run build` 后把 `dist/` 一起传上去。

### 4. 填生产配置

```bash
cd /opt/attendance/backend
cp .env.production.example .env
```

至少改这几行：

```ini
DEBUG=false
SECRET_KEY=<python -c "import secrets;print(secrets.token_urlsafe(48))" 的输出>
POSTGRES_PASSWORD=<一个强口令>
CORS_ORIGINS=https://你的域名
```

`DATABASE_URL` 里的密码要和 `POSTGRES_PASSWORD` 一致（模板里两处都写了占位符）。

### 5. 启动服务

```bash
cd /opt/attendance/backend
docker compose -f docker-compose.prod.yml up -d --build
```

### 6. 建表 + 导入基础数据（只做一次）

```bash
docker compose -f docker-compose.prod.yml run --rm api alembic upgrade head
docker compose -f docker-compose.prod.yml run --rm api python -m app.seed.run_seed
```

这两条命令分别做：按 Alembic 迁移脚本建表；把班级、教室、干事、排班、账号灌进数据库。
**账号初始口令统一是 `123456`，上线后第一件事就是让各班的学委改掉，运维端可以强制重置。**

### 7. 放证书并重启 nginx

```bash
cp fullchain.pem privkey.pem /opt/attendance/deploy/certs/
docker compose -f /opt/attendance/backend/docker-compose.prod.yml restart web
```

### 8. 验证

```bash
curl https://你的域名/api/health          # 应返回 {"status":"ok",...}
curl https://你的域名/                     # 应返回前端页面
```

## 三、日常运维

### 备份

```bash
/opt/attendance/deploy/backup.sh            # 默认输出到 /opt/attendance/backups
# 每天凌晨 3 点自动备份，保留 30 天：
#   crontab -e
#   0 3 * * * /opt/attendance/deploy/backup.sh >> /var/log/attendance/backup.log 2>&1
```

PostgreSQL 走 `pg_dump`，SQLite 直接复制文件；上传的假条 / 检讨附件一起打包。
**建议再把 `backups/` 同步一份到对象存储**（几十块钱一年），防止服务器故障导致备份一起丢。

恢复：

```bash
/opt/attendance/deploy/restore.sh backups/db-20261101-030000.sql.gz
```

### 更新版本

```bash
cd /opt/attendance
git pull                     # 或重新上传代码
npm run build                # 前端有改动时
cd backend
docker compose -f docker-compose.prod.yml run --rm api alembic upgrade head   # 有迁移时
docker compose -f docker-compose.prod.yml up -d --build
```

### 看日志

```bash
docker compose -f /opt/attendance/backend/docker-compose.prod.yml logs -f api
docker compose -f /opt/attendance/backend/docker-compose.prod.yml logs -f web
```

业务操作（谁改了应到人数、谁批准了调班）在系统的「运维端 → 操作日志」里看，不在容器日志里。

## 四、上线检查清单

- [ ] `DEBUG=false`，`SECRET_KEY` 已换成随机值（不是占位符）
- [ ] `CORS_ORIGINS` 写的是真实域名，没有 `*`
- [ ] 数据库口令不是默认口令
- [ ] 45 个账号的初始口令 `123456` 已逐个改掉（运维端可查看哪些还是初始口令）
- [ ] 每日备份任务已配置，且至少手工恢复演练过一次
- [ ] 服务器安全组只放行 80/443
- [ ] HTTPS 正常，浏览器地址栏没有「不安全」提示
- [ ] 手机浏览器打开首页能正常登录（学院的人主要用手机）

## 五、不用 Docker 行不行

行。`deploy/attendance.service` 是 systemd 单元文件，配合 nginx 部署：

```bash
cd /opt/attendance/backend
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/pip install "psycopg[binary]"
sudo cp /opt/attendance/deploy/attendance.service /etc/systemd/system/
sudo mkdir -p /var/log/attendance && sudo chown www-data:www-data /var/log/attendance
sudo systemctl daemon-reload && sudo systemctl enable --now attendance
```

PostgreSQL 需要单独装（`apt install postgresql`）或仍用云厂商的托管数据库。
容器化方案更省心（数据库版本、依赖、迁移环境都固定），推荐优先用 Docker。
