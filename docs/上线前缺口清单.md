# 上线前缺口清单

本文回答一个问题：**现在这套系统离「真的可以投入使用」还差什么，怎么补。**
配套文档：`上线部署指南.md`（服务器与域名）、`系统说明与技术选型.md`（功能与技术选型）。

---

## 一、一句话结论

功能链路已经跑通（登录 → 上报 → 核查 → 应到变更 → 调班 → 检讨 → 导出），
但处于「能演示、能试点」的状态，还不是「能长期无人值守运行」的状态。

代码侧的四项关键安全能力（弱口令整改、上传类型校验、登录限流、旧库结构自愈）已经就绪，
剩下的硬缺口集中在**真实名册数据、HTTPS/备案、备份调度、校历主数据**，
其中大部分是部署 / 运营动作而非写代码。

粗估完成度：功能约 **88%**，生产就绪度约 **70%**。

---

## 二、P0 · 不补就不能上线

| # | 缺口 | 状态 | 为什么是问题 | 怎么解决 | 工作量 |
|---|---|---|--------------|----------|--------|
| 1 | 库里是演示数据（班级、姓名、排班都是假的） | 待补 | 直接给师生用会看到假名字，且真实数据无法回填 | 用导入通道换成真实名册；建议做 Excel 导入脚本（班级/学生/干事/账号一次性灌入） | 1~2 天 |
| 2 | 弱口令批量重置 | 已具备 | 任何人知道学号/工号就能登录；学委能改别班数据 | `POST /api/ops/accounts/reset-random` 生成 10 位随机口令、一次性返回明文清单；上线前由运维执行 | 执行 5 分钟 |
| 3 | 首次登录强制改密 | 已具备 | 随机口令发下去，用户不改等于白做 | `accounts.must_change_password` + 业务接口 423 + 前端不可关闭改密页 + 口令强度策略 | 已完成 |
| 4 | 没有 HTTPS | 待补 | 口令在校园网明文传输，可被抓包 | nginx 配证书（云厂商免费证书或 certbot），HTTP 全量 301 到 HTTPS；模板见 `deploy/nginx/attendance.conf` | 0.5 天 |
| 5 | 备份脚本没人调度 | 待补 | 脚本写了但不会自动跑；硬盘/误删就没了 | 服务器上加 crontab：`0 3 * * * /opt/attendance/deploy/backup.sh`，并把备份同步到另一台机器或对象存储 | 0.5 天 |
| 6 | 域名与 ICP 备案未办 | 待补 | 国内云服务器 80/443 未备案会被阻断 | 先买域名并提交备案（7~15 个工作日，是最长的前置项，建议最早启动），期间可先用 IP + 自签证书内部测试 | 等待 1~3 周 |
| 7 | 上传文件类型校验 | 已具备 | 可以传 `.exe` / `.html`，存在存储型风险 | 扩展名白名单 + 文件头魔数 + docx 结构校验 + 服务端判定 MIME，不信任客户端 `Content-Type` | 已完成 |

## 三、P1 · 想稳定运行就得补

| # | 缺口 | 为什么是问题 | 怎么解决 | 工作量 |
|---|------|--------------|----------|--------|
| 8 | 没有学生名册表 | 请假、玩手机都靠手输姓名 → 错别字、同名、无法统计「某人本月第几次」 | 新增 `students` 表（学号/姓名/班级），前端改为下拉选择；支持按学号批量导入 | 2~3 天 |
| 9 | 没有校历 / 学期表 | 「周日到周四有晚自习」是硬编码常量，节假日停课、考试周都会算错排次与教室 | 新增 `term_calendar` 表，运维端维护「哪些日期有晚自习」；排次、教室规则统一读它 | 1~2 天 |
| 10 | 教室规则前后端两份 | 前端写死「周二 305、其余 303」，后端有 `ClassroomRule` 表 → 改一处忘另一处 | 前端改用 `/api/meta/rooms?date=` 的返回值，删掉前端硬编码 | 0.5 天 |
| 11 | 没有并发保护 | 两名干事同时核查同一班级，后写的会整份覆盖先写的 | `AttendanceRecord` 加 `version` 字段，更新时带版本号，冲突返回 409 让前端提示刷新 | 1 天 |
| 12 | 登录限流与锁定 | 弱口令 + 无限重试 = 可被暴力破解 | `login_attempts` 表按账号+IP 计数，5 次失败锁 10 分钟、成功后清零，支持 nginx `X-Forwarded-For`，并写审计日志 | 已完成 |
| 13 | 没有监控告警 | 服务半夜挂了，第二天早自习才发现 | systemd `Restart=always`（模板已配）+ 每分钟探测 `/api/health`，失败推送到企业微信/钉钉机器人 | 0.5 天 |
| 14 | 附件存在本地磁盘 | 换机器、容器重建、多实例部署都会丢文件 | 把 `files.py` 里的 `_write` / `_read_path` 换成对象存储 SDK（腾讯云 COS / 阿里云 OSS），路由不用改 | 1 天 |
| 15 | 没有通知触达 | 调班申请发出去了，对方不进系统就看不到 | 站内消息已有（`SwapNotice`），再加一层企业微信/微信模板消息推送 | 1~2 天 |
| 16 | 单进程 uvicorn | 撑不住开学季集中上报，且一崩全挂 | Docker 编排里已留多 worker 参数；建议 2 workers + nginx 前置 | 0.5 天 |

## 五、已经具备、不用再做的

- 真实口令哈希（bcrypt）+ JWT + 四角色接口鉴权，越权实测返回 403 / 401
- 跨周调班的双向互换与冲突拦截（前端与后端共用同一套校验规则）
- 应到人数变更的原因留痕 + 管理端「确认已阅」
- 考勤排次按「次」续排，锚点可在运维端改，跳过无晚自习的日子
- Alembic 版本化迁移 + 防漂移测试（改模型忘生成迁移会直接测试失败）
- 生产启动自检：`SECRET_KEY` 仍是占位值就拒绝启动；PostgreSQL 空库会提示先跑迁移
- Docker 生产编排（PG + API + nginx，数据库端口不对外）、备份/恢复脚本、systemd 单元
- 生产环境配置全走环境变量，迁移到云服务器不需要改任何业务代码
- 首次登录强制改密、口令强度策略、批量随机口令下发、登录失败限流与临时锁定
- 上传文件扩展名白名单 + 文件头校验 + 服务端判定 MIME
- 一键启动（Node 启动器，`--check` / `--verify` / `--smoke`），旧 SQLite 库自动补齐缺失列

## 六、建议的推进顺序

```
第 0 周
  └─ 提交域名 ICP 备案（周期最长，先启动）

第 1 周
  ├─ 导入真实班级 / 学生 / 干事 / 账号（#1）
  ├─ 批量重置随机口令 + 强制首次改密（#2 #3）
  └─ 上传类型白名单（#7）

第 2 周
  ├─ 学生名册表 + 前端改下拉选择（#8）
  ├─ 校历表 + 教室规则统一走后端（#9 #10）
  └─ 并发版本号、登录限流（#11 #12）

第 3 周
  ├─ 租服务器 + 部署 + HTTPS（#4 #6，配合 上线部署指南.md）
  ├─ 备份定时任务 + 健康检查告警（#5 #13）
  └─ 选 2~3 个班试运行两周

试运行通过后
  └─ 按 P2 逐项补：通知推送、统计报表、Cookie 化 Token……
```

**最小可上线集**：#1 #2 #3 #4 #5 #6 #7 —— 做完这七项就可以小范围真实使用，
P1 的 #8 #9 #11 建议在试运行期间同步补，因为它们直接影响数据质量。

## 七、一个务实的提醒

这套系统的真实并发量很小（6 个班 × 1 名学委 + 十几名干事，集中在 20:00–21:00 提交），
**1 核 2G 的云服务器足够**。不要为了「看起来专业」上微服务、Redis、消息队列——
现在这个单体 + PostgreSQL 的结构，出问题一个人就能排查完，这对校内自维护的系统最重要。
真正值得投入的是**备份**和**数据质量**（学生名册、校历），这两样决定了系统能不能用满一个学期。
