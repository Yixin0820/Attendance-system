## 五、上线前必须执行：批量重置随机口令

> ⚠️ **危险操作**：`reset-random` 会改写**所有启用账号**的口令，且明文只在本次响应里出现一次
> （数据库只存 bcrypt 哈希，事后无法找回）。执行前先备份 `backend/attendance.db`，
> 执行后**立即导出并线下分发**清单。建议在导入真实名册之后、正式对外开放之前做。

**先确认顺序**：导入真实班级/学生/账号 → 批量重置 → 分发口令 → 用户首次登录强制改密。

PowerShell（Windows，运维账号登录状态下执行）：

```powershell
$login = Invoke-RestMethod -Method Post `
  -Uri 'http://127.0.0.1:8000/api/auth/login' `
  -ContentType 'application/json' `
  -Body '{"username":"ops","password":"123456"}'

$headers = @{ Authorization = "Bearer $($login.accessToken)" }
$result = Invoke-RestMethod -Method Post `
  -Uri 'http://127.0.0.1:8000/api/ops/accounts/reset-random' `
  -Headers $headers -ContentType 'application/json' -Body '{}'

$result.items | Export-Csv -Path '账号口令清单.csv' -NoTypeInformation -Encoding UTF8
"共重置 $($result.count) 个账号"
```

只想重置某一类账号时，`-Body '{"role":"committee"}'`（可选 `committee` / `inspector` / `admin` / `ops`）。

**执行后的行为**：

- 口令为 10 位大写字母+数字（去掉了易混淆的 I/O/0/1），便于线下分发；
- 所有被重置账号被标记 `mustChangePassword=true`，首次登录会弹出**不可关闭**的改密页；
- 改密前除登录/改密/当前账号外的业务接口一律返回 423，防止临时口令被长期使用；
- 新口令至少 8 位，不能是 `12345678`、`password` 等弱口令，也不能与临时口令相同；
- **运维自己的 `ops` 账号也会被重置**，请务必保存好清单里对应的新口令。

单个账号忘记口令可用 `POST /api/ops/accounts/{username}/reset-password`（body `{"newPassword":"..."}`），
同样会触发首次登录强制改密。
